# 小改动部署复盘｜2026-11-06

这次只想更新贷款投资计算器的页脚。我把版本对齐、整站验收和 GitHub 文档更新都放到了发布前，最后一开始连发布都没做。用户明确说直接发之后，我把已保存的更新发布到原站点，Sites 返回成功。

## 时间花在哪里

- **追版本号。** 页脚写死了 Sites 版本和时间，但版本号由平台分配。为了让一行文字跟上版本号，每改一次再保存，就可能再产生一个版本。
- **查得比改得多。** 对照 Sites 和 GitHub、跑计算和图表回归、更新三份文档，都没解决这次最直接的任务：把页脚更新发出去。
- **把上一次失败当成这一次的结论。** 之前发布返回 `no healthy upstream`，原因未查明。后来用户明确要求直接发布，使用同一个已保存版本成功了。

## 下次怎么做

1. **先看改动本身。** 一行页脚就确认那一行。用户说版本号不用管，就跳过版本对齐。
2. **能用已保存的更新，就直接发布到原站点。** 需要改源码时，只改对应内容。验证范围跟着改动走。
3. **发布后确认结果。** 看平台是否报成功，有权限就打开页面确认那一行。遇到失败，记下错误和发布结果，避免连续重试。
4. **汇报一句话。** 成功就给链接，失败就说卡在哪。完整验收和项目文档有明确要求时再做。
